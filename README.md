# JUSTAY — Firebase-connected travel booking frontend

This version removes the hard-coded travel catalog, fake booking history, demo offers, local-storage booking stores, and simulated API responses. Catalog data is read from Cloud Firestore. Authentication uses Firebase Authentication. User bookings and wishlists are stored in Firestore and are scoped to the signed-in account.

## 1. Configure Firebase

1. Create a project in the Firebase Console.
2. Register a Web App in **Project settings → General → Your apps**.
3. Enable **Authentication → Sign-in method → Email/Password**.
4. Create a **Cloud Firestore** database.
5. Copy `.env.example` to `.env.local` and fill in the Web App configuration values:

```env
VITE_FIREBASE_API_KEY=your_api_key
VITE_FIREBASE_AUTH_DOMAIN=your_project.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=your_project_id
VITE_FIREBASE_STORAGE_BUCKET=your_project.appspot.com
VITE_FIREBASE_MESSAGING_SENDER_ID=your_sender_id
VITE_FIREBASE_APP_ID=your_app_id
```

Do not commit `.env.local` to source control. Firebase web configuration is intended to be used by client apps; protect data with Security Rules.

## 2. Apply Firestore security rules

Review `firestore.rules`, then deploy them with the Firebase CLI:

```bash
npm install -g firebase-tools
firebase login
firebase use --add
firebase deploy --only firestore:rules
```

The supplied rules allow public reads for catalog collections and only allow catalog writes from users with a trusted `admin` custom claim. User records such as bookings and wishlists are scoped to the authenticated user. Do not grant admin claims from client-side code.

## 3. Install and run

```bash
npm install
npm run dev
```

Open the local URL printed by Vite. Visit **Profile → Create an account** to register or sign in. The app does not create demo listings automatically. When Firebase is configured but no catalog records exist, the screens show empty states instead of fake examples. If Firebase configuration is missing, catalog reads now surface a configuration error instead of silently pretending the catalog is empty.

## 4. Firestore collections

Create documents in the collections below. Document IDs are generated by Firestore; include the fields required by the screen you want to populate.

- `packages`: `title`, `destination`, `duration`, `days`, `nights`, `tags` (array), `price` (number), `rating` (number), `reviewsCount` (number), `category`, `imageUrl`, `galleryImages` (array), `overview`, `inclusions` (array), `exclusions` (array), `highlights` (array), `itinerary` (array).
- `stays`: `name`, `location`, `city`, `rating`, `reviewsCount`, `pricePerNight`, `originalPrice`, `propertyType`, `starRating`, `amenities` (array), `mealPlan`, `breakfastIncluded`, `imageUrl`, `galleryImages` (array), `description`.
- `events`: `name`, `location`, `city`, `rating`, `reviewsCount`, `venuePrice`, `capacityMin`, `capacityMax`, `eventTypeSupported` (array), `availableSlots` (array), `foodAvailable`, `foodStartingPricePerGuest`, `amenities` (array), `imageUrl`, `galleryImages` (array), `description`, `venueFeatures` (array), `highlights` (array).
- `destinations`: `name`, `stateCountry`, `startPrice`, `imageUrl`, `packagesCount`, `staysCount`, `popularFor`.
- `offers`: `code`, `discountText`, `title`, `description`, `validTill`, `category`, `discountAmount`, `minBookingAmount`, `active`.
- `eventFoodPackages`: `name`, `pricePerGuest`, `description`, `inclusions` (array), `popular`.
- `coupons` / `packageCoupons`: `code`, `discountAmount`, `minBookingAmount` or `minAmount`, `active`.
- `rooms`: `hotelId`, `name`, `pricePerNight`, and the fields used by the room screen.
- `faqs`: `q`, `a`.
- User data collections are created by the app: `users`, `bookings`, `packageBookings`, `wishlists`, `notifications`, `reviews`, `packageReviews`, `supportTickets`, `payments`.

### Important notes

- Payment gateway integration is **not** configured. The app records booking requests and preferred payment method; it does not charge a card or claim a payment succeeded.
- SMS/email delivery is **not** configured. The notification API stores a notification record and explicitly does not claim that a message was sent.
- ID document images are not uploaded to Firebase Storage; base64 previews are not stored in Firestore documents and do not persist after reload. The UI does not mark IDs as verified or automatically confirm bookings. Before collecting real government ID data, implement Firebase Storage uploads with private per-user Storage Rules and a trusted review process, and review privacy/legal requirements.
- The client uses Firebase directly, so Firestore Security Rules are the backend authorization layer. Admin catalog editing should be done through a trusted admin environment or a server with Firebase Admin SDK—not by putting admin credentials in the browser.
